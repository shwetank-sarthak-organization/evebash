EVEBASH - TODO (NEW FEATURES)
=============================
New things we want to build (features and improvements), for the website and/or phone app.
Share this file in chats and keep it in the repo so everyone knows what is planned.

Which file to use:
- Bugs (something is broken)              -> evebash_issue.txt
- Checks by hand on a real device         -> test_yourself.txt
- New features and improvements (planned) -> this file

HOW TO USE
- New todo: add it at the end of ACTIVE TODOS with the "Next todo number" below, then increase
  that number by 1. Never reuse a number. Pull staging first so two chats don't take the same number.
- Starting work: set Status to "In progress" and Owner to your name.
- After discussing it: set Discussed to Yes and write what was agreed in Decision.
- Shipped (merged to staging): set Status to "Done" and add "Done in: <commit> (YYYY-MM-DD)".
  If it needs a check on a device, add a test in test_yourself.txt and note its number in Done in.
- Dropped: set Status to "Dropped" and say why in Decision.
- Delete Done and Dropped entries once they are older than 14 days.
- Dates are YYYY-MM-DD.

Field values:
- Platform:     App | Website | Both | Analytics dashboard | Backend only
- Priority:     High | Medium | Low
- Phase:        1 (v1 launch) | 2 (after launch, incl. business features) | 3 (later / nice to have)
                | TBD (not decided yet, e.g. "TBD (1 or 2, decide after discussion)")
- Status:       Idea | Agreed | In progress | Done | Dropped
- Effort:       S (a few hours) | M (1-3 days) | L (a week or more)
- Suggested by: a name, or where it came from (a user, an audit, a competitor)
- Discussed:    Yes | No
- Decision:     what was agreed when discussed, or "-"
- Owner:        a name, or Unassigned
- Depends on:   another todo, an issue number, a decision, or "-"

#17 Long videos: chunk-parallel decode for 4K sources on one GPU (switch, off)
Listed:       2026-10-27
Platform:     Both
Priority:     Medium
Phase:        TBD (decide after discussion)
Status:       Idea
Effort:       M
Suggested by: GPU transcode research 2026-10-27 (reports/GPU long-video transcode research 2026-10.md)
Discussed:    No
Decision:     -
Owner:        Unassigned
Depends on:   #15 and #16 are independent of it; player check of a chunked output first (see Brief)
Brief:        A single NVDEC session is the limit for 4K input (one decoder engine saturated, encoder
              36-38% busy). Encoding K time chunks with K ffmpeg processes on the same GPU, audio in a
              separate process, then joining the playlists, measured on the L4: 4K24 -46% (2 chunks) /
              -57% (4), iPhone 4K60 HDR -39% / -47%, 1080p -14% (2). Output content identical to today's
              (VMAF vs today 92-97, PSNR 47-57 dB), continuous timestamps, audio in sync. Recipe that
              works (two earlier versions did not): per chunk -ss S (+ -t as a bound), a trim=end=len
              filter before the split (not -t alone: it overshoots by the B-frame delay and leaves a
              stray boundary segment), -output_ts_offset S+1.0 and -start_number for every chunk, audio
              with -output_ts_offset 1.0 (without the constant, ffmpeg shifts chunk 0 by the B-frame
              delay and not the others); join playlists, drop a boundary segment listed twice, master
              from a single-process layout, then today's full-length check. The joined output has only
              been checked with ffprobe and VMAF, never in a player: play one on iOS, Android, Safari and
              hls.js, seeking across a chunk boundary, before the switch goes on.
Update:      2026-10-27: chunks = number of video decoders on the card (RTX 4000 Ada 2, L4 4,
              Blackwell slice 1 = no chunking). Measured with p3 + 6 s GOP + upload while encoding, 3 runs:
              RTX 4000 Ada test_5 136 s / ₹2.44 (today 209 s / ₹3.63), HDR 94 s / ₹1.74 (132 s / ₹2.36);
              Modal L4 4K24 69 s (125 s), test_5 161 s (224 s). Player check still missing (reports/Final video pipeline recommendation 2026-10-27.md).
Update:      2026-10-27: cut chunks at the exact time of the first frame after each 6 s mark, not at round
              6 s: round cuts repeat one frame per cut on 23.976 fps footage (1,201 vs 1,200 frames, video then 42 ms late).
              Frame-exact cuts verified frame-for-frame on 23.976 fps, 60 fps and variable-frame-rate iPhone clips. Chunk
              only long videos (4 chunks on 5 s pieces cost up to 0.3 VMAF GPU / 1.3 CPU). RTX 4000 Ada strict recipe:
              test_5 163 s / ₹2.68 (today 207 s / ₹3.38), HDR 95 s / ₹1.56 (134 s / ₹2.19). CPU 32 vCPU with 4 chunks:
              test_5 200 s / ₹1.95 (today 275 s / ₹2.67), HDR 143 s / ₹1.39 (223 s / ₹2.16).
